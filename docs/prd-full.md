# StyleGrabber — 통합 PRD (Product Requirements Document)

## 1. 개요

- **제품명:** StyleGrabber
- **목표:** 다수의 경쟁사 디자인 시스템을 수동으로 분석하는 디자이너의 번거로움을 해결함.
- **핵심 가치:** URL 리스트 입력만으로 각 웹사이트의 타이포그래피/스타일 정보를 추출하여, 표준화된 **디자인 시스템 테이블**로 피그마 캔버스에 자동 생성.

## 2. 타겟 유저

- 경쟁사 벤치마킹 및 디자인 시스템 구축 업무를 수행하는 UI/UX 디자이너.

---

## 3. 기능 요구사항

### 3.1. 사용자 입력 (Input)

- **Bulk URL Input:** 텍스트 영역(Textarea)을 통해 다수의 URL을 줄바꿈으로 구분하여 한 번에 입력.
- **Scope:** 로그인 불필요한 공개 웹사이트(Public URL) 한정.

### 3.2. 추출 및 처리 (Processing)

- **Sequential Processing:** 입력된 URL 리스트를 순차적으로 처리하여 시스템 부하 방지.
- **HTML/CSS Parsing:** Puppeteer headless로 대상 사이트의 타이포그래피(폰트, 사이즈, 웨이트 등) 데이터를 Computed Style 기반으로 파싱.
- **Error Handling:** 분석 실패 시 해당 URL을 건너뛰고 오류 메시지를 출력한 뒤 다음 URL로 즉시 이동.

### 3.3. 시각화 (Output)

- **Standardized Table Generation:** 파싱된 데이터를 정형화된 표(디자인 시스템 스타일)로 디자인하여 피그마 캔버스에 자동 배치.
- **Layout Rule:** 사이트별로 고정된 간격(예: 500px)을 유지하며 가로로 나열.

---

## 4. 시각적 고도화 (Visual Enhancement)

추출된 데이터를 단순히 텍스트 테이블로 보여주는 것을 넘어, 피그마 내에서 바로 디자인 가이드로 활용할 수 있도록 시각적 구조와 샘플링 기능을 강화함.

### 4.1. 시각적 샘플 렌더링 (Visual Sampling)

- **타이포그래피 카드:** 폰트 스타일(Family, Size, Weight) 정보뿐만 아니라, 해당 스타일이 적용된 텍스트 샘플(예: "Aa Bb Cc 123")을 카드 형태로 자동 생성.
- **컬러 스와치(Swatch):** 텍스트로만 표시되던 색상 코드 옆에, 해당 색상이 적용된 원형/사각 박스(Swatch)를 배치. `node.fills` 속성으로 HEX 값을 실제 컬러 레이어로 매핑.

### 4.2. 구조화된 디자인 가이드 레이아웃

- **섹션별 그룹화:** 추출된 요소들을 'Typography', 'Color Palette' 섹션별로 분리하여 레이아웃. 각 섹션마다 헤더(Header) 및 구분선 적용.
- **Auto Layout 적용:** 생성되는 모든 컴포넌트와 테이블에 피그마 Auto Layout을 적용하여, 수동 수정 시에도 레이아웃이 무너지지 않도록 함.

### 4.3. 비교 요약 대시보드 (Dashboard)

- **비교 분석 대시보드:** 여러 경쟁사의 데이터를 추출했을 때, 캔버스 좌측에 각 사이트별 핵심 수치(가장 많이 쓰인 컬러 3개, 주력 폰트 사이즈 등)를 요약한 '비교 요약 시트' 생성.

---

## 5. 전문가 분석 기능 (Expert Analysis)

디자이너가 추출 결과를 즉시 인사이트로 활용할 수 있도록, 의미론적 분석과 패턴 도출 기능을 추가한다.

### 5.1. 의미론적 분석 (Semantic Tagging)

- 단순히 속성값만 추출하지 않고, 해당 스타일이 주로 쓰이는 DOM 요소(예: button, h1~h6, input)를 태깅하여 의미를 부여함.

### 5.2. 사용 빈도 및 규칙 분석 (Pattern Analysis)

- 추출된 스타일들의 사용 빈도를 계산하여, 해당 사이트에서 가장 핵심적으로 관리하는 스타일을 식별함.
- 수치들이 특정 그리드 시스템(예: 4px, 8px 스케일)을 따르는지 판단하여 가이드라인 도출.

### 5.3. 비교 분석 모드 (Comparison Mode)

- 복수의 URL 분석 시, 공통되는 디자인 언어와 차별화되는 지점을 비교 테이블로 시각화.
- 컴포넌트 규격(버튼 사이즈, 인풋 높이, 둥글기 등)을 추출하여 '인터랙션 시스템 가이드' 생성.

---

## 6. 디자인 분석 솔루션 고도화 (Design Audit)

단순한 스타일 데이터 추출을 넘어, 디자이너가 경쟁사를 분석하고 자사 디자인 시스템의 의사결정 근거를 마련할 수 있도록 '데이터 해석 및 진단(Insight)' 기능을 강화함.

### 6.1. 디자인 시스템 파편화 분석 (Fragmentation Analysis)

- **유사값 그룹핑(Clustering):** 미세하게 다른 값(예: 17px와 18px)을 설정 가능한 오차 범위 내에서 하나의 '시스템 스타일'로 묶어 표기.
- **파편화 경고:** 동일한 역할(예: `h3`)인데 스타일이 3개 이상 분산되어 있을 경우 '파편화 위험(Fragmentation Alert)' 배지 표시.

### 6.2. 의미론적 위계 재구성 (Semantic Hierarchy)

- **역할 기반 그룹핑:** 추출된 요소를 [제목(Heading)], [본문(Body)], [버튼/인터랙션(Action)] 그룹으로 자동 분류.
- **시스템 뷰(System View):** 각 그룹 내에서 사용 빈도가 가장 높은 스타일을 'Base'로 설정하고, 변형된 스타일은 서브 요소로 재배치하여 위계를 명확히 함.

### 6.3. 디자인 진단 리포트 (Design Audit Insights)

- **일관성 배지(Consistency Badge):** 해당 스타일이 전체 페이지의 80% 이상에서 일관되게 사용되는지 수치화.
- **위계 오류 탐지(Anomaly Detection):** 상위 헤더보다 하위 헤더가 더 크거나, 의미 없는 폰트 변형이 발견될 경우 '시스템 점검 필요' 경고 메시지 노출.
- **그리드/스케일 진단:** 폰트 크기나 간격이 특정 규칙(예: 8px 그리드, 1.25 Type Scale)에 부합하는지 계산하여 '시스템적 정합성' 수치 표시.

---

## 7. 리포트 기반 스마트 렌더링 (Smart Rendering)

기존 감사 결과를 기반으로 데이터를 정제하고, 정제된 시스템 뷰와 원본 뷰를 전환할 수 있는 기능을 제공한다.

### 7.1. 데이터 정제 엔진 (Data Cleaning Engine)

- **Threshold 적용:** Consistency 50% 미만인 스타일은 '비표준'으로 분류하여 숨김 처리 옵션 제공.
- **Clustering 정제:** 유사한 값(FontSize ±1px, FontWeight 등)을 빈도수 기반으로 단일 토큰으로 병합.
- **Priority Sorting:** 빈도수(Count)가 높은 순서대로 테이블 상단 배치.

### 7.2. System View 자동 생성

- **Semantic Mapping:** 리포트의 진단 결과를 바탕으로 h1~h6, body, caption 등의 위계를 가진 '정제된 테이블' 렌더링.
- **Insight Tagging:** 각 스타일 옆에 리포트 결과(예: "Most Consistent", "System Base")를 작은 라벨로 표시.

### 7.3. UI 인터랙션

- **"Cleaned Version만 보기" 토글:** 전체 추출 데이터와 정제된 시스템 데이터를 전환하며 볼 수 있는 기능.

---

## 8. 멀티 페이지 통합 렌더링 (Multi-Page Integration)

단일 URL 분석의 한계를 극복하고, 여러 핵심 페이지(메인, 상세, 폼 등)를 분석하여 서비스 전체의 '진짜 디자인 표준'을 피그마에 시각화함.

### 8.1. 데이터 통합 (Data Aggregation)

- **Global Token 추출:** 복수의 URL에서 80% 이상의 일치율을 보이는 스타일을 'Primary System Token'으로 우선순위 부여.
- **중복 제거:** 동일한 CSS 속성을 가진 스타일은 하나의 카드로 병합하되, 어느 페이지들(URL)에서 발견되었는지 태그 표시.

### 8.2. 피그마 레이아웃 구조화

- **[Frame 1] 메인 분석 (Main Insight):** 첫 번째 입력된 URL의 스타일 리포트.
- **[Frame 2] 시스템 공통 (Global Standard):** 모든 입력 페이지에서 공통 추출된 정제된 타이포/컬러 테이블.
- **[Frame 3] 컴포넌트 규격 (Component Specs):** 인풋, 버튼 등 여러 페이지에서 공통 발견된 UI 규격 데이터.

### 8.3. 시니어 디자이너를 위한 가치

- **데이터 신뢰도:** "메인에만 있는 스타일인가요?"라는 질문에 "아니요, 5개 서브 페이지에서도 공통 사용되는 표준입니다"라고 확신 있게 대답 가능.
- **시스템 구축 속도:** 여러 페이지를 직접 들어갈 필요 없이, StyleGrabber가 정제해준 '교집합' 데이터만 보고 바로 디자인 시스템 초안 완성.

## 9. 기술 스택

| 항목 | 선택 | 근거 |
|------|------|------|
| 서버 프레임워크 | Express | 가벼운 프록시 서버에 적합, 빠른 세팅 |
| HTML 파싱 | Puppeteer (headless) | Computed Style 접근 필요, SPA 대응 |
| 빌드 도구 | esbuild | Figma 플러그인 빌드 속도 최적화 |
| UI 프레임워크 | React | 플러그인 UI 구성 |
| UI 상태관리 | React useState | 단순 UI로 별도 상태관리 라이브러리 불필요 |
| 언어 | TypeScript | 전체 |
| 플랫폼 | Figma Plugin API | 캔버스 렌더링 |

## 10. 기대 효과

- **생산성:** 디자이너가 별도의 가이드 문서 작업 없이, 플러그인 결과물만으로 바로 '디자인 가이드라인' 산출 가능.
- **인사이트:** 단순히 "이런 색을 쓰네"에서 "이 사이트는 8px 그리드 시스템을 기반으로 일관된 폰트 위계를 사용하고 있구나"라는 분석 가능.
- **의사결정:** 파편화된 스타일을 정리하는 시간을 대폭 단축하여, 디자인 시스템 구축 초기의 '기준 수립' 속도를 향상.
- **전문성:** 단순 추출기를 넘어, 디자인 시스템 컨설팅 수준의 분석 결과 제공 가능.
